## UX Changes Made This Session

Here are the new user-facing features added:

---

### **1. Checkout - Family Members Step** (During Enrollment)

**Where:** Step 2 of the enrollment wizard (between "Plans" and "Payment")

**What users can do:**
- Click **"Add a family member"** button to open an inline form
- Enter: First name, Last name, Email, Relationship (Spouse/Child/Domestic Partner/Other)
- See **live pricing** showing: Primary plan cost + (# dependents × dependent cost per person)
- **Remove** any dependent from the list before checkout
- **Skip** (continue without dependents) or **Continue** with dependents

**Visual indicators:**
- Each dependent shows as a card with name, relationship, email, and cost
- Total price at bottom reflects all family members
- "Step 2 Family (Optional)" label indicates it's not required

**How to test:**
```
1. Go to /health/enroll
2. Select a plan → Continue
3. Fill personal info → Continue
4. Click "Add a family member"
5. Fill in dependent details for 1-2 people
6. See order total update on the right sidebar
7. Proceed to payment
```

---

### **2. Dashboard - Family Members Section** (After Enrollment)

**Where:** `/health/dashboard` → Overview tab → "Family Members" card (below "Account Information")

**What users can do:**
- **View** all dependents linked to their account with:
  - Name, relationship, email
  - Status badge: "Active" (claimed account) or "Invite Pending" (not yet signed up)
- **Add** a new family member mid-subscription via inline form
- **Resend** the invite link if the initial email was missed (for pending dependents)
- **Remove** a dependent with a confirmation dialog

**Primary member view:**
- Shows list of all family members
- "Add Member" button at the top
- Each dependent has actions: Resend (if pending) or Remove

**Dependent view:**
- Shows "Managed by [Primary Name]" (they see the dashboard but can't add/remove members)

**How to test:**
```
1. Log in as a primary member who has dependents
2. Go to /health/dashboard
3. Scroll to "Family Members" section
4. Try clicking "Add Member" → fill form → save
5. Try clicking "Resend" on a pending dependent
6. Try clicking the trash icon to remove a dependent
```

---

### **3. Invite Claim Page** (Dependent Sign-Up Flow)

**Where:** `/health/claim-invite?token=<inviteToken>` (emailed to dependent)

**What happens:**
- **If not logged in:** Shows claim info + sign-up/sign-in buttons with return URL preserved
- **If logged in:** Shows "Accept & Get Access" button
  - Clicking it binds their Clerk account to the dependent profile
  - Redirects to their dashboard
- **Error states:** Invalid token, already claimed, etc.

**How to test:**
```
1. Add a dependent from dashboard → get invite email (check your email or logs)
2. Click the "Accept & Get Access" link
3. If not signed in → sign up → auto-redirects to claim
4. If signed in → claim button appears → click it
5. Should redirect to /health/dashboard as the dependent
```

---

### **4. Checkout Page - Dependent Pricing Display**

**Where:** Right sidebar order summary during checkout (`/health/checkout`)

**What changed:**
- New line item showing: **"X Family Members @ $Y/person"** when dependents are enrolled
- **Total Due Today** includes: primary rate + (# dependents × dependent rate)
- Billing statement text updates when dependents are added: *"...I will be billed $X today and $X/mo on renewal (includes 2 family members)."*

**How to test:**

2. Look at the order summary on the right
3. See breakdown: "Primary: $50/mo" + "2 Family Members: $25/mo each ($50 total)" = "$100/mo"

## Quick Reference: User Flows

### **Primary Member Adding a Dependent During Checkout:**
```
Checkout page → Family Members step → 
  Fill form (name, email, relationship) → 
  See pricing update → 
  Complete payment → 
  Dependent gets invite email
```

### **Primary Member Adding a Dependent Later (Dashboard):**
```
Dashboard → Family Members section → 
  "Add Member" button → 
  Fill form → 
  Dependent invited immediately → 
  Resend option if needed
```

### **Dependent Claiming Their Account:**
```
Receive email invite → 
  Click "Accept & Get Access" → 
  Sign up (if not logged in) → 
  Automatically claim → 
  See dashboard (read-only, no billing)
```

### **Dependent Dashboard Experience:**
```
Can see:
  ✅ Active plans & benefits
  ✅ Member card
  ✅ Oral scan, teledentistry access
  ✅ "Managed by [Primary]" info

Cannot see:
  ❌ Billing/payment methods
  ❌ Subscription management
  ❌ Renewal dates (pricing details)
```

## Key Design Points to Know

| Feature | Behavior |
|---------|----------|
| **Dependent limit** | None (unlimited dependents per primary) |
| **Pricing model** | Per-member add-on (primary $50/mo + each dependent $25/mo, configurable) |
| **Invite expiry** | 30 days (but "Resend" generates new token) |
| **Billing isolation** | Dependents can't change payment or cancel; all billing happens under primary's account |
| **Access derivation** | Dependents automatically get all entitlements the primary has (no separate billing row) |
| **Member card** | Each dependent gets their own card with their name & member ID |
| **Dashboard access** | Dependents see benefits but no financial info |

## Where to Click to Use Each Feature

| Feature | URL | Who | Action |
|---------|-----|-----|--------|
| Add during checkout | `/health/enroll` → Step 2 | Primary (new) | "Add a family member" |
| Manage after signup | `/health/dashboard` → Family Members | Primary (existing) | "Add Member" / "Remove" / "Resend" |

| View as dependent | `/health/dashboard` | Dependent (claimed) | Read-only view (no billing) |

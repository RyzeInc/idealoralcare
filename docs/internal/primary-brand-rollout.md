# AssureVantage is the primary brand

The owner's final November 3 correction governs: AssureVantage is the new business brand on `www.assurevantage.com` only. Marketing on `getidealoh.com` is frozen at pre-session commit `43aaa07`, retaining Ideal identity. The earlier change that made both homepages AssureVantage was a misunderstanding and has been reversed. No domain forwarding from Ideal to the new homepage is configured.

The AssureVantage site is classified as `primary`. The original Ideal site/group records remain available for legacy groups, including CMG/Soars and Wellness Patriots. Their memberships, vendor access codes, prices and existing Ideal materials are not migrated by the new-brand launch. Admin site lists label those records as Legacy Ideal.

New public program links stay under `/assurevantage`: `plans` for oral savings, `essentials`, `balance-for-life`, `oralcare`, `program-plans`, `program-checkout` and `program-success`. These reuse the existing program components and billing flow. They attribute new orders to the AssureVantage hierarchy. Existing `/health` and `/newideal` paths remain the legacy experiences. On AssureVantage, `/assurevantage` redirects to its own root page, retaining referral parameters. Every request to an `/assurevantage` page on getidealoh.com, including sign-in, checkout and receipt, redirects to the corresponding AssureVantage URL. Existing Ideal marketing URLs never redirect to the new brand.

The existing oral catalog, Essentials tiers, BFL and oral add-on catalog entries are offered through the main brand. The separately requested CMG/Soars benefit replacement is not activated by this marketing restoration. Legacy program pages retain their existing presentation and vendor instructions.

Member branding covers oral, Essentials and standalone BFL emails, packet PDFs and cards for AssureVantage enrollments. Essentials support remains `info@getidealhealth.com` / 844-433-2502; oral support remains `support@getidealoh.com` / (844) 679-9367. Existing vendor access codes remain in the member instructions. Branded packets use the native BFL app QR page rather than an Ideal-branded vendor appendix.

On November 18, 2026 the owner swapped the Clerk domains: assurevantage.com is now the primary authentication host and getidealoh.com its satellite, so an AssureVantage visitor never lands on a getidealoh.com URL. The same Clerk instance and user directory serve both domains. getidealoh.com sign-in, sign-up and password-reset pages hand off to `https://www.assurevantage.com/assurevantage/sign-in` (or `sign-up`/`forgot-password`) with Clerk's sync parameters and return to the original getidealoh.com destination. The production publishable key encodes the primary Frontend API host, so the swap requires the `clerk.assurevantage.com` publishable key in Vercel.

Deployment: deploy the updated backend and frontend, then run the internal `admin/launchSites:configureAssureVantage` setup with `{"promoteToPrimary":true}`. This is an idempotent promotion/catalog update; it does not rename or move legacy groups. Existing support, payment and vendor validation items in the email audit remain open unless separately verified.

Setup also requires a visible standalone `bfl-individual` product with monthly card and ACH pricing and Stripe product mappings. It always includes that product in AssureVantage's allowed plans. If the product is missing in a new environment, provide `bflStripeProductId` when running setup; this creates only the missing BFL catalog entry at $19.95/month, using the supplied Stripe product for that environment. Provision and verify a test-mode Stripe product for development and a live-mode product for production before supplying its ID. Existing products, prices, mappings and visibility are preserved. Missing or incomplete BFL configuration fails setup with an actionable error. Historical duplicate Ideal slugs are tolerated by reading the oldest active template without modifying the legacy records.

## Shared AssureVantage cart (November 5, 2026)

`/assurevantage/program-plans` is the shared three-offering catalog. It starts with an empty cart and uses the same `assurevantage` local-storage namespace as every program and oral page. `/assurevantage/program-checkout` is the shared checkout entry; `/assurevantage/checkout` redirects there, preserving query parameters. Oral-only orders retain their selected billing cadence. Essentials and standalone Balance for Life force the whole order to monthly billing, including when restoring an old saved cart. Selecting Essentials replaces standalone BFL because it is included. Selecting a different Essentials or oral tier replaces the previous tier. The checkout API also rejects annual membership orders and Essentials/BFL combinations.

Retail checkout now uses one `UnifiedCheckout` component for Oral Care, Essentials, Balance for Life and mixed orders. All orders show Review Your Order, Payment Method, Account, Agent / Rep Selection and Confirm & Pay before authentication. The signed-in account and every required signature are needed only before proceeding to Stripe. Agreement storage failures block payment; changing the account, price, cadence or payment method invalidates prior consent.

Since the November 18 domain swap, the AssureVantage public checkout and receipt run on `https://www.assurevantage.com/assurevantage/program-checkout` and `program-success`, the Clerk primary, so the inline account wizard handles account creation/sign-in in Step 3 without leaving the domain. Visitors go to the full checkout, never a standalone sign-in page. Earlier links that carried a `?cart=` selection to getidealoh.com are redirected to assurevantage.com, where the validated selection is restored from current visible/allowed catalog products; no profile, password, payment credentials or supplied prices are transferred. Existing Ideal marketing and its original checkout destinations remain unchanged.
